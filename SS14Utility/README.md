# SS14 Utility

Одна настольная программа (.NET/WinForms) с тремя вкладками:

- **MIDI-плеер** — звучит так же, как инструменты в билде МК
  ([dead-space-server/space-station-14-soyuz](https://github.com/dead-space-server/space-station-14-soyuz)),
  чтобы слушать и подбирать миди, не заходя в игру.
- **Картинка → текст** — превращает фото в SS14 rich-text «картинку» (текст, который в игре выглядит
  как изображение). Порт [SSfyImage](https://github.com/Tunguso4ka/SSfyImage) (Python/PyQt6, автор
  Tunguso4ka) на C#.
- **Карточка персонажа** — из 4 PNG-экспортов внешности (фас/спина/слева/справа) и текстовых полей
  (имя, возраст, должность, лор, навыки) собирает карточку персонажа в стиле настольных D&D-листов,
  экспорт в PNG или PDF.

## Запуск

```bash
dotnet run -c Release --project SS14Utility.csproj
```

Или собрать и запустить exe напрямую:

```bash
dotnet build -c Release SS14Utility.csproj
"bin/Release/net8.0-windows/win-x64/SS14Utility.exe"
```

## Вкладка «MIDI-плеер»

Внутри тот же синтезатор (fluidsynth через `SpaceWizards.NFluidsynth` и `Robust.Natives.Fluidsynth` —
ровно те пакеты, что тянет клиент игры), те же саундфонты и портированная логика инструментов из
`Content.Client/Instruments` и `RobustToolbox/Robust.Client/Audio/Midi`. Файлы можно бросать в окно
перетаскиванием, папку — тоже.

**Инструменты.** Все 70 сущностей билда с компонентом `Instrument` — от рояля и скрипки до
велосипедного клаксона, КПК музыканта и суперсинтезатора. Для каждого берутся ровно те поля, что
стоят в прототипе: `program`, `bank`, `allowPercussion`, `allowProgramChange`, `respectMidiLimits`.
Названия — русские из локализации игры.

**Стили.** У 12 инструментов есть `SwappableInstrument` (то самое ПКМ-меню в игре): гитара
Clean/Jazz/Muted, бас Fingered/Pick/Slap, саксофон Soprano/Alto/Tenor/Baritone, микрофон с
Kweh/Waa/Wah из кастомного банка 100 и так далее. Стили выбираются выпадающим списком.

**Логика воспроизведения — порт `MidiRenderer.SendMidiEvent`:**

- когда `allowProgramChange: false` (а это почти все инструменты), команды смены программы и банка из
  файла игнорируются, а на все каналы кроме ударного принудительно ставится программа инструмента —
  поэтому в игре скрипка играет скрипкой весь файл;
- когда `allowPercussion: false`, канал 9 (десятый, ударный) глушится;
- `SystemReset` из файла возвращает инструмент на его собственную программу, а не на ту, что записана
  в миди;
- фильтрация любых каналов — как меню каналов в игре, с названиями треков и именами GM-программ,
  вытащенными тем же парсером (`Content.Client/Instruments/MidiParser`).

**Ручной режим.** Program 0–127, Bank и список GM-инструментов доступны напрямую — можно услышать
любую программу, даже ту, которой нет ни у одного игрового инструмента. Кнопка «Сбросить к прототипу»
возвращает настройки инструмента.

**«Играть как слышат другие».** Локально исполнитель всегда слышит файл целиком, а по сети идёт
ограниченный поток: `midi.max_events_per_batch` (60 событий за тик), `midi.max_events_per_second`
(1000) и `midi.max_lagged_batches` (8), после чего сервер перестаёт ретранслировать музыку, а игроку
сводит пальцы и оглушает. Галка прогоняет воспроизведение через ту же очередь: видно события в
секунду, длину очереди, задержку и момент, когда музыка оборвалась бы. У суперсинтезатора админский
`respectMidiLimits: false`, и лимиты на него не действуют — здесь тоже.

**Прочее.** Повтор, пауза, перемотка, громкость, «Паника» (сброс зависших нот, аналог `midipanic`),
предупреждение о файлах тяжелее 2 МБ — игра такие не принимает.

### Саундфонты

Грузятся в том же порядке, что и в клиенте (каждый следующий перекрывает предыдущий):

1. `soundfonts/fallback.sf2` — из движка (`Resources/Midi/fallback.sf2`, взят из
   `284.0.2.zip` в кэше лаунчера);
2. `C:\Windows\system32\drivers\gm.dls` — системный; fluidsynth не считает `.dls` саундфонтом и
   пропускает его, так же как и в игре;
3. `soundfonts/GeneralUser-GS.sf2` и `soundfonts/space-station-14.sf2` — из
   `Resources/Audio/MidiCustom` билда МК; второй как раз даёт кастомные банки (клаксон, вокал микрофона);
4. всё, что лежит в `%APPDATA%\Space Station 14\data\soundfonts` — как и в игре, перекрывает остальное.

Кнопка «Саундфонты» показывает, что именно загрузилось.

### Обновление данных из репозитория

Каталог инструментов и названия программ вытащены скриптами `tools/*.py` из клона билда МК
([dead-space-server/space-station-14-soyuz](https://github.com/dead-space-server/space-station-14-soyuz))
и его RobustToolbox. Сами клоны в репозиторий не входят (слишком большие и не нужны для сборки) —
если билд обновится, склонируйте их рядом заново:

```bash
git clone --filter=blob:none https://github.com/dead-space-server/space-station-14-soyuz repo
git -C repo submodule update --init RobustToolbox

python tools/extract_instruments.py repo Assets/instruments.json
python tools/extract_programs.py repo Assets/programs.json
dotnet build -c Release SS14Utility.csproj
```

Саундфонты копируются вручную из `repo/Resources/Audio/MidiCustom` в `soundfonts/`.

### Проверка без окна

```bash
SS14Utility.exe --selftest "путь\к.mid" ViolinInstrument 6 --limits
```

Пишет лог в `%TEMP%\ss14midiplayer-selftest.log`: какие саундфонты загрузились, что за инструмент,
какие треки распознаны, как идёт воспроизведение и что показывает симулятор лимитов. С
`--render out.wav` звук пишется в файл (сырой PCM 16 бит, 44100, стерео) вместо колонок, с
`--maxeps N` лимиты искусственно занижаются, чтобы посмотреть, как звучит обрыв.

## Вкладка «Картинка → текст»

Загружает изображение (файл, кадр GIF, буфер обмена или встроенная рисовалка) и превращает его в SS14
rich-text разметку — текст с тегами `[color=#RRGGBB]`, который в игре на листе бумаги выглядит как
картинка.

**Источник.** Файл, кадр анимированного GIF (WEBP/APNG грузятся статично — GDI+ не даёт им листать
кадры), вставка из буфера обмена, или рисование от руки во встроенном пиксель-арт редакторе
(карандаш/заливка/линия/прямоугольник, отражения, поворот на 90°, симметрия, бесшовный тайл-режим,
изометрическая сетка-подсказка, undo).

**Коррекция.** Полный `#RRGGBB` или укороченный (1 hex-цифра на канал — как ограничение обычного
неполного цветового тега) режим, dither (сглаживает укороченный режим), Ч/Б, инверсия, яркость,
контраст, постеризация, сдвиг оттенка, палитра из любого референсного изображения (медиан-каскад).

**Перекраска.** Клик по превью выбирает цвет-источник, второй клик — целевой цвет из палитры Windows,
кнопка заменяет все вхождения.

**Символ.** Любая пара символов вместо стандартного `██` (пресеты: блоки, стрелки, ромбы, звёзды и
т.д.), либо режим «тени», где плотность символа (`░▒▓█`) следует за яркостью пикселя.

**Размер.** Ручной ввод, сохранение пропорций, быстрый прирост +2/+4, «по размеру листа» (21x26 —
стандартный лист SS14), «по лимиту символов» (бинарным поиском ужимает картинку, пока полный текст не
влезет в лимит).

**Вывод.** Копирование в буфер, сохранение/загрузка текста (загрузка умеет распарсить свою же разметку
обратно в картинку), сохранение превью как PNG, генератор normal map (экспорт-ассет для освещения во
внешнем движке — самому SS14 он не нужен), превью «как будет выглядеть под Game Boy/NES/Sega
Genesis/аркадный CRT» (только для предпросмотра, не влияет на сохранённый текст).

## Вкладка «Карточка персонажа»

Собирает карточку персонажа в стиле настольных D&D-листов из четырёх PNG-экспортов внешности и
текстовых полей.

**Вход.** Четыре PNG отдельно: фас, спина, слева, справа (например, экспорт внешности персонажа из
игры). Имя, возраст, должность, лор/история, список навыков (по одному на строку, вида
«Название: уровень»). Любое поле можно оставить пустым — на карточке будет плейсхолдер («нет фото»,
«— не указаны —» и т.д.), а не пустое место или ошибка.

**Карточка.** Пергаментный фон с виньеткой, орнаментальная рамка с уголками, фас — крупным портретом,
три остальных ракурса — миниатюрами под ним, блок навыков (маркированный список с чередующейся
заливкой строк), блок лора (курсив, авто-подбор размера шрифта под текст). Короткие списки/лор не
«прилипают» к верху бокса — центрируются по вертикали.

**Экспорт.** PNG (для шаринга) и PDF (для печати, ~150 DPI). PDF собирается вручную, без внешних
библиотек — одна страница с одним растровым изображением, встроенным без потерь (FlateDecode, не
JPEG), чтобы текст на карточке не терял чёткость.
